2. Guia de Uso: Sistema de Controle de Pagamentos (|Diretor Finaceiro)

CONTROLE DE PAGAMENTOS: CLIQUE AQUI PARA ACESSAR CONTROLE DE PAGAMENTOS

O Diretor Financeiro acessa o sistema via link na Área Administrativa

Estrutura de Dados Crítica

  • Atenção aos Nomes das Abas: O sistema depende de nomes de abas fixos na planilha: **CADASTRO**, **VALORES**, **PENDÊNCIAS**, **SUMÁRIO DO CAIXA** e **CALENDARIO_PGTO_AAAA**. **Não renomeie nenhuma dessas abas**, pois isso quebrará o App Script.
  • Base de Dados: As abas **CADASTRO** e **VALORES** são a base de dados. Mantenha as colunas originais e preenchidas de forma precisa, sem reordenamento.
  • Calendário Anual: O sistema gera uma nova aba **CALENDARIO_PGTO\_[ANO]** automaticamente no início do ano. Verifique se os dados na aba **VALORES** estão configurados para o novo ciclo antes que a nova aba seja criada.

Fluxo Operacional de Registro

  • Prioridade da Senha: A **Senha de Registro** (definida nas Propriedades do Script) é **obrigatória** para qualquer registro de pagamento. Ela garante a segurança dos lançamentos.
  • Seleção Mensal : Ao registrar um pagamento, certifique-se de selecionar o **Mês** correto no formulário. É o mês de referência para o pagamento que está sendo efetuado.
  • Registro de Novos Membros: Ao usar o formulário de registro, se o membro for novo, marque a opção correspondente. O script irá **adicionar automaticamente** o nome e o valor da mensalidade (se fornecido) na aba **CADASTRO** antes de registrar o pagamento.
  • Timestamp de Lançamento: O sistema registra o pagamento com a **data e hora exatas** do momento em que o formulário é submetido, funcionando como uma auditoria de lançamento.

Comando Principal: Publicação (`push_to_git_v2.ps1`)

  • Função: Automatiza o fluxo de trabalho Git: adiciona todas as alterações , e envia para o GitHub .
  • Ação: Após salvar TODAS as mudanças nos arquivos, rodar: .\push_to_git_v2.ps1
  • Mensagem: Sempre use uma mensagem de confirmação clara (Ex: "Atualizado Irmandade").

Checklist Antes de Publicar

  • Verificar o Status Local: Antes de rodar o script, execute git status. Certifique-se de que todos os arquivos que você editou (HTML, CSS, etc.) estão listados e prontos para o *commit*.
  • Conflitos: Se o git status indicar "Conflitos", **NÃO** rode o `push_to_git_v2.ps1`. O código precisa ser resolvido manualmente.
  • Conexão: Erros de conexão ou autenticação impedirão o `git push`.

Comando de Emergência: Restauração (`restore_state.sh`)

Este script é a "cápsula do tempo". Ele permite voltar o código de um arquivo, pasta ou do site inteiro para uma versão anterior que estava funcionando, corrigindo erros críticos de forma rápida.

  • Uso: **SOMENTE em CASO DE ERRO GRAVE** (site quebrado, arquivos deletados, erro de código visível na página).
  • Ação: Rodar o script no terminal: ./restore_state.sh
  • Local de Execução: A partir do diretório raiz C:\WALDECK_IA (ou /mnt/c/WALDECK_IA no WSL).
Funcionamento do Script (Passo a Passo)
  1. Exibição do Histórico: O script primeiro lista os **últimos 10 commits** (mensagens de publicação) que foram feitos no site.
  2. Pergunta 1: Digite o SHA:
    • O que é SHA? É o número de identificação único daquela versão do código (o "log"). Ex: 4a3db9a. Você deve olhar a lista exibida e digitar o SHA da **última versão que você lembra que estava funcionando corretamente**.
  3. Pergunta 2: O que restaurar?
    • '.' (Ponto): Restaura **TODO** o projeto para a versão do SHA escolhido (uso mais comum em emergências).
    • Nome da Pasta (Ex: GALERIA): Restaura apenas o conteúdo daquela pasta específica.
    • Nome do Arquivo (Ex: index.html): Restaura apenas o arquivo HTML para a versão escolhida.
  4. Execução: Após as respostas, o script automaticamente restaura os arquivos locais, faz um novo commit com a mensagem de restauração e envia a versão corrigida para o GitHub, fazendo o Netlify publicar o estado anterior.
AVISO IMPORTANTE: A restauração irá **perder** quaisquer alterações locais que você tenha feito e não salvou no GitHub (que não foram rodadas com o push_to_git_v2.ps1). Use-o com cautela.
